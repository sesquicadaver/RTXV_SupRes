RTX VSR — локальний відеопроксі.
Бінарники програми: Program Files. Профілі, результати бенчмарків і журнали лишаються в каталозі користувача (QStandardPaths) і під час оновлення та видалення не чіпаються.

Видалення програми не видаляє спільний Microsoft Visual C++ Runtime і драйвер NVIDIA.

Мережа: інсталятор не відкриває порти брандмауера. Якщо правило знадобиться, воно має стосуватися лише rtx-vsr-proxy.exe і конкретного режиму прийому, а не діапазону портів для всієї системи.

Сторонні компоненти постачаються лише тими бібліотеками, які дозволяє ліцензія саме використаної версії:

- Qt 6: динамічне компонування. Потрібна LGPL або комерційна ліцензія Qt. Вихідний код відповідної версії Qt або письмова пропозиція надати його має лежати поруч із пакетом (third-party/QT_SOURCE_OFFER.txt).
- FFmpeg: динамічна збірка LGPL. Прапорці --enable-gpl і --enable-nonfree заборонені. Пропозиція вихідного коду: third-party/FFMPEG_SOURCE_OFFER.txt.
- NVIDIA RTX Video SDK і CUDA runtime: до пакета входять лише файли, які ліцензія використаного SDK дозволяє розповсюджувати разом із застосунком. Перелік фіксує third-party/NVIDIA_RUNTIME.txt. CUDA Toolkit, Visual Studio, CMake, MSYS2 і повний SDK на комп'ютер користувача не ставляться.
- Microsoft Visual C++ Runtime x64: офіційний інсталятор усередині пакета. Запускається лише коли встановлена збірка x64 відсутня або старіша за зафіксовану. Новіший сумісний runtime не замінюється.

Драйвер NVIDIA: якщо вже стоїть сумісний, пакет працює без інтернету. Інакше запускається лише офіційний підписаний пакет із контрольною сумою з маніфесту. Адаптер поза переліком supported_device_ids не отримує «приблизний» драйвер.

Маніфест packaging/components.json фіксує версії, архітектуру, контрольні суми, мінімальний драйвер і PCI device id. Порожній перелік GPU або нульовий мінімальний драйвер зупиняє пакування.
